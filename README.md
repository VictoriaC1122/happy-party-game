# 快樂酒局派對遊戲

繁體中文版、主持人開房型的多人派對網頁遊戲。這個版本保留原作的風險判斷、標籤線索、試紙與醫院檢查等節奏，並重構成最多 40 人可同步加入的現場活動版。

## 玩法摘要

- 主持人建立房間後，會生成房號與 QR Code。
- 玩家掃碼或輸入房號加入，等待主持人開始。
- 開局後，系統會在全體玩家中隨機指定 6 位初始帶原者。
- 6 位初始帶原者會在第 1 Round 私下收到身分與陣營任務；主持人大螢幕及其他玩家不會看到。
- 全局共 10 Round。
- 每局限時 45 秒；倒數結束仍未選擇的玩家會自動提交「換一個」，翻牌與終局復盤也會照此記錄。
- 每 Round 重新隨機兩兩配對，並優先避開連續遇到同一位玩家。
- 第 1 Round 不會觸發任何亂入或失控事件；第 2 Round 起，欲求不滿值從 25% 進入失控抽選，觸發率會從 8% 升到最高 70%。
- 戴套口交與戴套性交會小幅增加欲求不滿值；換人、撲空或去醫院增加得更多，無套互動則會降低。
- 失控事件會隨機強制套用無套性交，或以「你不想」鎖住戴套口交與戴套性交。
- 帶原者每次成功無套性交都會累積氣勢：第 2 次起讓之後遇到他的玩家額外抽戴套選項上鎖，機率依序為 25%、40%、55%，第 5 次起封頂 70%。
- 焦慮得病值每累積 25% 會在每局多遮一條線索；達到 80% 後無法再靠聊天取得對方資訊。
- 感染狀態預設隱藏，每位玩家整晚只有 1 次偷驗對方、1 次去醫院驗自己的機會。醫院會讓焦慮得病值歸零，並只讓本人知道自己的檢測結果。
- 隨機事件「對方偷偷戳破套子」會在翻牌時將戴套口交改判為無套口交、戴套性交改判為無套性交，並依無套風險與分數結算。
- 所有會改變本局規則的事件都會用玩家專屬彈窗通知；多個事件同時撞上會依序顯示，偷偷戳破套子則在翻牌改判時才揭曉。
- 感染者不會提早出局，後續親密互動仍可能繼續擴散。
- 若玩家終局前從未有過任何一次親密互動，直接判定失敗。
- 帶原陣營終局只要達成任一條件就獲勝：6 位初始帶原者合計直接感染 6 人、由後來感染者合計間接感染 15 人，或所有曾有親密互動的玩家全部感染。
- 若帶原陣營未達成上述任務，先淘汰零親密互動者，再由生存分最高的 6 人獲勝；健康者優先，感染者只遞補空缺。
- 生存分為：健康 +120、每次親密 +4、每次戴套 +7、驚險避過感染 +10、正確換人 +7、偷驗 +5、醫院 +3；每次無套 -9、每次傳播 -10，初始帶原者任務失敗再 -30。
- 終局的全感染條件會先排除零親密互動者；他們直接失敗，即使仍保持健康也不影響帶原者判定。
- 主持人與玩家終局都會看到 6 人頒獎舞台及全員成績單。
- 單機測試台可切換「模擬帶原者視角」，輪看 6 位初始帶原者的感染狀態、傳播次數、親密次數與陣營任務；正式玩家畫面不會曝光。

## 檔案結構

- `index.html`: 主畫面與多人流程骨架
- `styles.css`: 介面樣式與舞台視覺
- `data.js`: 遊戲規則、標籤、台詞、動作數值
- `app.js`: 房間同步、主持人邏輯、回合結算、終局頒獎

## 技術方式

- 前端純靜態，適合 GitHub Pages。
- 即時同步使用 PeerJS，主持人瀏覽器即為房主權威節點。
- QR Code 由前端動態產生，不需伺服器。

## 本地預覽

在專案資料夾執行：

```bash
python3 -m http.server 4173
```

然後打開：

```text
http://localhost:4173
```

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新 repo，例如 `happy-party-game`
2. 把這個資料夾內的檔案放進 repo 根目錄
3. 推到 `main` 分支
4. 到 GitHub repo 的 `Settings > Pages`
5. `Build and deployment` 選 `Deploy from a branch`
6. Branch 選 `main`，資料夾選 `/ (root)`
7. 儲存後等待 GitHub Pages 生成網址

## 注意事項

- 這是主持人房主架構，所以主持人的頁面不能在遊戲進行中關閉。
- 玩家若中途斷線，系統會保留其資料，但該局會被視為未主動提交。
- 目前環境尚未直接接上 GitHub 帳號 API，因此 repo 建立與推送可能需要在有 GitHub 權限的環境完成。
