# 快樂酒局派對遊戲

繁體中文版、主持人開房型的多人派對網頁遊戲。這個版本保留原作的風險判斷、標籤線索、試紙與醫院檢查等節奏，並重構成最多 40 人可同步加入的現場活動版。

## 玩法摘要

- 主持人建立房間後，會生成房號與 QR Code。
- 玩家掃碼或輸入房號加入，等待主持人開始。
- 開局後，系統會在全體玩家中隨機指定 6 位初始帶原者。
- 全局共 10 Round。
- 每 Round 重新隨機兩兩配對，並優先避開連續遇到同一位玩家。
- 焦慮值越高，下一 Round 隨機遇到感染者的機率越高；達到 80% 後會看花部分線索。
- 滿足值越高，下一 Round 隨機遇到感染者的機率越低，並會在每局多揭露線索。
- 感染狀態預設隱藏，每位玩家整晚只有 1 次偷驗對方的機會。
- 感染者不會提早出局，後續親密互動仍可能繼續擴散。
- 若玩家終局前從未有過任何一次親密互動，直接判定失敗。
- 若終局時仍有人保持健康，先淘汰零親密互動者，再由生存分最高的 6 人獲勝；健康者優先，感染者只遞補空缺。
- 生存分為：健康 +120、每次親密 +4、每次戴套 +7、驚險避過感染 +10、正確換人 +7、偷驗 +5、醫院最多 +6；每次無套 -9、每次傳播 -10，初始帶原者任務失敗再 -30。
- 終局先排除零親密互動者；他們直接失敗，也不參與全感染判定。
- 若其餘有親密互動的玩家全部感染，6 位初始帶原者直接共同獲勝，即使觀望者仍保持健康也不影響結果。
- 主持人與玩家終局都會看到 6 人頒獎舞台及全員成績單。

## 檔案結構

- `index.html`: 主畫面與多人流程骨架
- `styles.css`: 介面樣式與舞台視覺
- `data.js`: 遊戲規則、標籤、台詞、動作數值
- `app.js`: 房間同步、主持人邏輯、回合結算、終局頒獎

## 技術方式

- 前端純靜態，適合 GitHub Pages。
- 即時同步使用 PeerJS，主持人瀏覽器即為房主權威節點。
- QR Code 由前端動態產生，不需伺服器。

## 本地預覽

在專案資料夾執行：

```bash
python3 -m http.server 4173
```

然後打開：

```text
http://localhost:4173
```

## 部署到 GitHub Pages

1. 在 GitHub 建立一個新 repo，例如 `happy-party-game`
2. 把這個資料夾內的檔案放進 repo 根目錄
3. 推到 `main` 分支
4. 到 GitHub repo 的 `Settings > Pages`
5. `Build and deployment` 選 `Deploy from a branch`
6. Branch 選 `main`，資料夾選 `/ (root)`
7. 儲存後等待 GitHub Pages 生成網址

## 注意事項

- 這是主持人房主架構，所以主持人的頁面不能在遊戲進行中關閉。
- 玩家若中途斷線，系統會保留其資料，但該局會被視為未主動提交。
- 目前環境尚未直接接上 GitHub 帳號 API，因此 repo 建立與推送可能需要在有 GitHub 權限的環境完成。
